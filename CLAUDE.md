## SOCIAL-QUOTES IMAGE HOSTING

All Coach Jeff social-media quote-card images live at `public/social-quotes/*.jpg` in this repo, and are served at `https://www.coachjeff.ai/social-quotes/*.jpg` (Vercel's Output Directory setting maps `public/` to site root -- do not add a `/social-quotes` rewrite in vercel.json, it's not needed and was tried/reverted once already, see commit c4fa0a7).

To add new images: add files under `public/social-quotes/`, commit, push to `main` -- Vercel auto-deploys to Production. This is the ONLY correct hosting location for these images. (Two other repos -- `mybff-coach` and `mybffcoach-website` -- were checked and ruled out on 2026-09-02: neither hosts coachjeff.ai content; `mybffcoach-website`'s index.html title doesn't even match the live site.)

### HOW TO ACTUALLY PUSH NEW SOCIAL-QUOTES IMAGES FROM A CLOUD AI SESSION (added 2026-09-04)

If you're an AI assistant working from a cloud session with only a device-bridge into Rusty's Mac (not a full local dev shell), plain `git` will NOT work here -- don't waste time on it. What was actually tried and what actually works, in order of discovery:

1. **Local git via the device-bridge shell fails, two different ways.** `git clone`/`git commit`/`git add` inside a connected/mounted folder (anything under the bridge's `mnt/<folder>` paths) fails with `Unable to create '.../.git/config.lock' or '.../index.lock': File exists` -- the sandboxed shell blocks file deletion by default, including git's own internal lock-file cleanup, so the operation always dies at that step regardless of how "fresh" the directory is. Cloning outside the mounted paths (true local scratch on that shell, e.g. plain `$HOME`, not under `mnt/`) avoids the lock-file problem but then hangs indefinitely on HTTPS auth -- there's no `gh` CLI, no cached credential, no keychain access from that shell, so a private-repo clone just waits forever for a password that will never come. Don't retry either of these -- they're structural, not flaky.
2. **The GitHub API tools (`create_or_update_file` / `push_files`) work but don't scale to full-size images.** They're the right call for text files (this file included), but base64-encoding a ~500KB JPG is ~650KB of text, and inlining 10+ of those in one exchange is slow, wasteful, and risks hitting practical per-message output limits. Fine for one or two small images; not for a batch.
3. **What actually works for a batch of images: browser automation on Rusty's own logged-in GitHub session.** Navigate to `https://github.com/coach-rusty/coachjeff-site/upload/main/public/social-quotes`, use the browser tool's file-upload action pointed at the image files (paths from the AI's own cloud workspace are fine -- the browser's native upload dialog reads bytes directly off disk, so it never touches the AI's own token/context budget), type a commit message, click "Commit changes." This commits straight to `main` and Vercel deploys to production within roughly 30-60 seconds. Verified 2026-09-04 with a 14-image batch (the `CJ_NIGHT2_*` night quote-cards).
4. **Always verify afterward, don't just assume it worked:** `curl -s -o /dev/null -w "%{http_code}" https://www.coachjeff.ai/social-quotes/<filename>.jpg` for every file just pushed, and pull the commit with `get_commit(..., include_diff:true)` to confirm every changed file shows `"status": "added"` -- never `"removed"` on anything you didn't intend to touch. This second check is what would have caught the 2026-09-02 sparse-checkout incident immediately instead of an hour later.
